Phase 번호가 아닌 책임 기준 패키지

public List<Document> search(String question, int topK, double threshold) {
    SearchRequest request = SearchRequest.builder()
        .query(question)
        .topK(topK)
        .similarityThreshold(threshold)
        .build();
    return vectorStore.similaritySearch(request);
}

SELECT metadata->>'file_name' AS "fileName",
       metadata->>'chunk_index' AS "chunkIndex",
       content,
       ts_rank_cd(
         to_tsvector('simple', COALESCE(content,'')),
         websearch_to_tsquery('simple', :question)
       ) AS "keywordScore"
FROM public.vector_store
WHERE to_tsvector('simple', COALESCE(content,''))
  @@ websearch_to_tsquery('simple', :question)
LIMIT :topK;
ReciprocalRankFusion.java
private double calculateScore(int k, int rank) {
    return 1.0 / (k + rank);
}
// 청크 ID 기준으로 키워드·벡터 순위를 병합 후 합산
fusedResult.score += calculateScore(k, result.rank());

// RRF 점수 내림차순 + 동점 chunkId 정렬
.sorted(comparingDouble(MutableFusedResult::score)
    .reversed()
    .thenComparing(MutableFusedResult::chunkId))

Engineering Notes

실패를 숨기지 않은 기술적 판단

결과가 좋지 않았던 지점도 원인 추적을 위한 데이터로 보존했습니다.

Phase 1 · 페이지 추적 한계

453페이지 처리 대비 페이지 Document 416개. 통합 후 청킹으로 청크별 정확한 페이지 범위 추적 불가.

Phase 2 · 검색 파라미터

Top-K 5에서는 정답 누락, Top-K 10에서 9위로 발견. Threshold 0.5 이상에서는 결과 전체 제거.

Phase 3 · Advisor Grounding

수동 Retrieval 결과가 0개인데 Advisor는 일반 지식 형태 답변을 생성해 Grounding 위험을 관찰.

Phase 4 · 0점 기준선

Hit/Recall/Precision/MRR 모두 0이었지만 평가 기준과 원본 결과를 고정해 Phase 5 비교의 기준으로 사용.

Phase 5 · 리랭킹 미수행

키워드·벡터 후보가 모두 0이어서 리랭킹 후보도 0. 적용 조건 미충족으로 리랭킹 비교를 수행하지 않음.

Phase 6 · Graph 필터 효과 없음

Graph Traversal은 성공했지만 corpus가 단일 문서라 문서 범위 축소 효과가 없고 Retrieval 지표도 개선되지 않음.
